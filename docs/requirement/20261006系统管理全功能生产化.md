# 需求草稿：系统管理全功能生产化

> 输入：用户直接指令（2026-10-06）——「帮我完成系统管理下所有功能，是生产级可用的，每个功能都是可以点击使用的。不是 demo。」
> 本草稿按 SDD 流程覆盖更新，作为 openspec 提案 `complete-sysadmin` 的输入。

## 现状

系统管理目前只有「组织与权限」（用户/角色 CRUD）进入生产（openspec: add-ops-admin）。
高保真原型（prototype/src/pages/admin/）已定义完整产品形态并确认：

| 原型页 | 功能 | 生产状态 |
|---|---|---|
| Overview | 系统运营总览（资产/调用/服务健康/告警） | ❌ 未进入生产 |
| Users / Roles | 用户与角色管理 | ✅ 已上线（admin/org） |
| Menus | 菜单管理（排序/显隐/路由） | ❌ 导航为前端硬编码 |
| Permissions | 权限管理（功能矩阵/行级规则/敏感级继承） | ❌ 仅原型静态数据 |
| Monitor | 依赖服务监控（巡检/可用率） | ❌ 仅原型静态数据 |
| Logs | 日志查询（检索/详情/导出） | ❌ 无审计日志表 |
| Settings | 个性化设置（仅影响本人） | ❌ 无持久化 |

## 目标（生产级 = 真实 API + 真实持久化 + 真实生效，非静态展示）

1. **系统运营总览**：全平台指标由真实库表计数聚合（本体/对象/实例/数据源/知识/能力/调用/评审/管道/审计事件），服务健康取最近巡检结果，最近告警取审计 WARN/ERROR。
2. **菜单管理**：菜单树入库（menus 表）；生产前端导航由 `/api/v1/menus` 驱动（隐藏即从导航移除）；支持新增/编辑/显隐/删除（有子菜单 409）；按当前用户角色权限过滤导航。
3. **权限管理**：
   - 功能权限矩阵：由 roles.perms 实时派生，点击单元格可切换角色模块权限（写回角色）；
   - 数据权限（行级规则）：data_rules 表 CRUD，角色引用校验（400）；
   - 敏感级继承：由 views.upstream × datasources.sensitive 实时推导（取上游最高），只读展示。
4. **依赖服务监控**：dep_services/dep_checks 表；「手动巡检」对 PostgreSQL（自库）/Redis/MinIO 执行真实健康检查（探活 + 延迟采样），更新状态并落检查历史；7 日可用率由检查历史按日聚合。
5. **日志查询（审计）**：audit_logs 表；所有 /api/v1 写操作（POST/PUT/DELETE）由中间件自动记录（模块/级别/操作人/TraceID，2xx=INFO、4xx=WARN、5xx=ERROR）；支持模块/级别/关键字/时间范围过滤 + 分页 + CSV 导出。
6. **个性化设置**：user_settings 按账号持久化；主题（浅/深/跟随系统）、密度、等宽字体**真实全局生效**（ConfigProvider/body class）；默认落地页（首次进入跳转）、默认本体（顶栏初始值）、通知类别过滤（首页消息中心）真实生效。

## 用户体验关键点

- 系统管理 导航扩展为 7 个叶子：系统运营 / 组织与权限 / 权限管理 / 菜单管理 / 服务监控 / 日志查询 / 个性化设置。
- 顶栏提供演示用户切换（localStorage 持久化）：切换后导航按该用户角色权限过滤、本体 myRole 联动、个性化设置按账号隔离——使权限治理效果可观察。
- 写操作幂等（客户端 id）+ 校验错误以中文明确提示（沿用全仓约定）。

## 非目标

- 登录认证与会话安全（后续提案）；菜单变更「发布」流程（直接生效）；通知渠道投递（飞书/邮件，仅类别过滤）；监控告警规则配置与主动告警。
