# 需求草稿：清除模块编号（全仓去编号式标识）

> 输入：用户直接指令（2026-10-06，转述）——所有代码和文档里都不要再出现编号式的模块字符，一律用有含义的词。

## 现状

上一轮（meaningful-routes）完成了生产前端路由与三重内部标识（菜单 id / 权限键 / 审计模块）的语义化，
但模块编号仍残留在：

1. **生产代码注释**：backend/frontend 各文件头注释与分段注释；
2. **seed 叙事**：demo 数据文案（如管道名、审计叙事中的模块指代）；
3. **原型 prototype/**：完整路由体系（编号命名的页面目录、路由表、导航、编号前缀的组件名）、
   mock 数据与页面文案（含编号式功能号）；
4. **文档**：README、AGENTS、docs/requirement/*、docs/architecture/*、openspec/specs 与
   changes/archive/* 历史提案、CHANGELOG。

## 目标

全仓不再出现任何编号式模块标识，指代一律用有含义的词：

- **路由 / 权限键 / 审计模块**：英文模块键 `assets / knowledge / modeling / runtime / reasoning / sandbox / apps / governance / admin`（与生产路由对齐）；
- **中文注释与文档叙述**：中文模块名（数据资产 / 知识运营 / 本体建模 / 本体运行时 / 推理演绎 / 推演沙盘 / 智能应用 / 治理演化 / 系统管理），编号直接删除；
- **编号式功能号**：废弃，用功能名本身表达；
- **原型路由**：模块前缀与叶子全部语义化（编号前缀一律换成语义前缀，如数据资产页 → `/assets/...`、系统管理页 → `/admin/...`），
  组件标识去掉编号前缀，页面目录按语义命名。

## 非目标

- 架构图 PNG 若无法本地重渲染则仅更新 Mermaid 源文件（图内旧编号以源文件为准后续再渲染）；
- git 历史中的旧字符（不可改写，也不应改写）。
