# 草稿需求（docs/requirement/）

这里是 SDD 流程的**入口**：所有需求先在本目录落成草稿，作为 openspec 提案的输入。

## 命名约定

```
YYYYMMDD需求描述.md        例：20261006本体注册中心查询.md
```

## 流程

1. 新需求 → 在本目录创建草稿（谁提的、要解决什么问题、期望的样子）
2. 与用户对齐需求分析后**覆盖更新**草稿
3. 创建 openspec 提案时（`openspec/changes/<change-id>/proposal.md`）引用对应草稿作为上下文
4. 提案归档后，若需求涉及既有说明文档，同步更新

草稿是工作文档，允许粗糙；规格（openspec/specs/）才是权威。
