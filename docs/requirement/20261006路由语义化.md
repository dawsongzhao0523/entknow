# 需求草稿：全站路由语义化（去 m1-m9）

> 输入：用户直接指令（2026-10-06）——「所有路由的 url 都是用具有含义的单词，不要使用 m1-m9 这种 api 接口路由。」

## 现状

生产前端全部路由形如 `/m1/datasources`、`/m9/settings`——模块编号对使用者无含义，观感像内部 API 编号。
`m1-m9` 同时是三个内部标识的取值：菜单表一级 id（= 路由前缀）、角色权限键（roles.perms）、审计模块标签（audit_logs.module，日志页过滤项）。

## 目标

1. 前端路由全部换成有含义的英文单词，层级保持「模块前缀/功能」两级：

| 模块 | 前缀 | 子路由 |
|---|---|---|
| 数据资产 | assets | /assets/datasources · /assets/views · /assets/pipelines |
| 知识运营 | knowledge | /knowledge/entries · /knowledge/synonyms |
| 本体建模 | modeling | /modeling/ontologies · /modeling/registry |
| 本体运行时 | runtime | /runtime/instances · /runtime/rules |
| 推理演绎 | reasoning | /reasoning/query |
| 推演沙盘 | sandbox | /sandbox/compare |
| 智能应用 | apps | /apps/capabilities |
| 治理演化 | governance | /governance/reviews |
| 系统管理 | admin | /admin/overview · /admin/org · /admin/permissions · /admin/menus · /admin/monitor · /admin/logs · /admin/settings |

2. 三处内部标识同步切换为新键（保证权限过滤与审计过滤不失效）：
   - 菜单表一级 id / 子路由（= 导航与权限引用键）；
   - 角色权限键 roles.perms（seed 六角色）；
   - 审计模块标签（audit 中间件路径映射 + 日志页过滤选项 + seed 叙事行）。
3. 页内跳转、设置页落地页选项、通知 to_path、回退导航常量全部对齐。
4. `/api/v1/*` 后端 API 路径本身不含 m1-m9，不动。

## 非目标

- 旧 m1-m9 地址的兼容重定向（无外部使用方，demo 库 `make demo` 重置即一致）；
- prototype/ 原型的路由（PM 专用高保真原型，独立信息架构，不随生产路由演进）。
